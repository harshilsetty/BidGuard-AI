# SIH26100 Team Guide

## Mission

Build a working MVP for AI-assisted bid compliance verification for GeM procurement.

### Core Application Flow:

```
Tender PDF
   ↓
Requirement Extraction
   ↓
Bidder Documents
   ↓
Evidence Extraction
   ↓
Evidence Matching
   ↓
Rule Validation
   ↓
PASS / FAIL / REVIEW
   ↓
Evidence & Source Page
   ↓
Dashboard
   ↓
Report
```

---

## Team Rules

1. **Working functionality is more important than feature count.**
2. **Do not change architecture without discussing it with the Team Lead.**
3. **Do not directly push to main.**
4. **Every feature must have a Git branch.**
5. **Pull the latest develop branch before starting work.**
6. **Commit frequently.**
7. **Create a PR when work is ready.**
8. **Never commit API keys or secrets.**
9. **Never claim fake government integrations or fake accuracy.**
10. **If blocked for more than 30 minutes, report it.**
11. **Keep communication concise and technical.**
12. **Do not duplicate another teammate's work.**
13. **Before adding a new dependency, check whether an existing dependency can solve the problem.**
14. **Do not spend time polishing features that are not part of the golden demo.**

---

## Golden Rule

> **"Show what is working, not what you are planning."**
